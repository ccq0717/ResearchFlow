当前全栈实现地图

从现象出发，快速定位负责的层、核心文件和调试入口。

层负责什么核心文件首先在哪里观察
Dashboard目标输入、创建按钮、历史列表apps/web/src/app/page.tsx浏览器页面和 Console
前端 API 客户端组织 HTTP 请求、解析 JSONapps/web/src/lib/api.tsNetwork 面板
Research Workspace显示任务、计划、SSE 进度和报告apps/web/src/app/research/[runId]/page.tsxNetwork 中的 /events
FastAPI 路由HTTP 与应用用例之间的转换apps/api/src/researchflow/api/routes.py后端终端和 API Docs
应用层创建任务、安排工作流application/research_runs.py任务状态与单元测试
工作流接口隔离模拟与真实规划执行workflows/base.py装配配置和工作流测试
模拟工作流不联网推进阶段、生成事件和报告workflows/simulated.pySSE 日志和任务进度
LLM 规划工作流生成并保存真实结构化计划workflows/llm_research.py研究计划和失败代码
LLM 适配器封装 HTTP、鉴权、Schema 和解析integrations/llm/适配器测试和后端错误
Repository保存、查询、更新任务、计划和事件persistence/repository.py数据库记录和测试
数据库连接创建 Engine、Session 和表persistence/database.py后端启动和数据库文件
SQLite 文件持久保存任务、计划、事件和报告var/researchflow.db文件存在性和只读查询

创建任务的主路径

page.tsx 表单
  → lib/api.ts 发送 POST
  → api/routes.py 接收
  → ResearchRunApplication.create_run()
  → SqliteResearchRepository.create()
  → var/researchflow.db
  → HTTP 201 + run.id 返回前端

LLM 计划与实时进度的主路径

LLMResearchWorkflow → LLMClient → research_plans
  → research.plan.completed
  → 前端读取 /plan 并展示

SimulatedResearchWorkflow 或 LLMResearchWorkflow
  → Repository 保存 research_events
  → FastAPI StreamingResponse
  → 浏览器 EventSource
  → React 状态更新
  → 进度条和实时日志重绘
定位原则：页面样式先看组件；请求失败先看 Network 和路由；状态错误看应用层与工作流；刷新后数据错误看 Repository 和 SQLite；实时更新错误看事件表与 SSE。
