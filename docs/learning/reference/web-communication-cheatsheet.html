Web 通信方式速查表

先问“数据由谁发起、需要往几个方向流动、更新频率多高”，再选择通信方式。

方式方向适合场景ResearchFlow 示例
普通 HTTP / REST前端请求，后端一次响应创建、读取、修改、删除数据创建研究任务；读取最终报告
轮询 Polling前端定时重复请求更新不频繁，实现优先简单每两秒查询任务状态（当前未采用）
SSE连接建立后，后端持续推送进度、日志、通知、文本流实时推送研究阶段和进度
WebSocket前后端都可随时发送聊天、协作编辑、实时游戏未来需要双向实时协作时才考虑
当前选择：ResearchFlow 使用普通 REST 创建和读取任务，使用 SSE 接收执行进度。这不是二选一，而是各自处理适合的问题。

SSE 四个关键字段

eventSSE 事件名称；持久化研究事件统一使用 research.event
data事件携带的数据；项目中使用 JSON 字符串
id事件序号；断线重连和去重时使用
retry建议浏览器断线后等待多久再重连，单位为毫秒
