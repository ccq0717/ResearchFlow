Lesson 0011 · 约 75 分钟

前端怎样把持续变化的研究运行变成可读页面

这一课把 React 状态、REST 快照、SSE 增量事件和 Markdown 报告串起来，解释刷新恢复与实时更新为什么可以同时成立。

先记结论：SQLite 中的数据是真相来源，REST 负责取得完整快照，SSE 只推送此后发生的变化；Markdown 渲染器负责展示，不负责判断研究结论是否正确。

0. HTML、CSS 和 JavaScript 各做什么

技术全称/含义职责
HTMLHyperText Markup Language，超文本标记语言标题、段落、表格等页面结构
CSSCascading Style Sheets，层叠样式表颜色、尺寸、间距和响应式布局
JavaScript浏览器编程语言事件、状态、请求和动态行为

React 最终仍然创建 HTML 对应的 DOM 元素并应用 CSS，不是替代 Web 基础。

0.1 DOM 是什么

DOM 全称是 Document Object Model，中文是“文档对象模型”。浏览器把 HTML 解析成一棵可操作的节点树。React 根据组件输出计算哪些 DOM 节点需要更新。

document
└─ main
   ├─ h1 研究结果
   └─ section
      └─ p 报告内容

0.2 JSX、TSX 和组件

JSX 允许在 JavaScript 中写接近 HTML 的界面语法；TSX 是包含 TypeScript 类型的 JSX 文件。它会在构建阶段转换成 JavaScript 调用。组件名大写，接收 props 并返回界面描述。

1. Dashboard 和研究页各自负责什么

app/page.tsx 保存输入框、文档选择和历史列表等短暂界面状态。创建接口返回运行 ID 后，路由跳转到 /research/[runId]。

research/[runId]/page.tsx 不依赖 Dashboard 留在内存中的数据，而是根据 URL 中的运行 ID 重新读取后端。因此直接打开链接或刷新浏览器都能恢复页面。

2. 三类状态不要混在一起

状态例子丢失后果
React 本地状态按钮是否正在提交、弹窗是否打开刷新后重置，不影响研究数据
REST 快照运行、计划、材料、历史事件和度量可从 SQLite 重新读取
SSE 增量新阶段、进度和终态事件断线后按序号补取历史

研究页先并行读取运行、计划和材料，再读取事件历史；若任务尚未结束，才从最后一个事件序号之后建立 EventSource。这样不会把“连接成功”误认为“数据已经完整”。

2.1 useState 为什么触发重新渲染

useState 为组件保存值和更新函数。调用更新函数后，React 再次执行组件，使用新值计算界面。不要直接修改旧数组或对象；项目用 setEvents(current => merge(...)) 基于最新状态产生新数组。

2.2 useEffect 的建立与清理

Effect 用于让组件和网络连接等外部系统同步。研究 ID 改变时建立新的加载与 SSE 流；返回的 cleanup 会把 cancelled 标记设为 true 并关闭旧 EventSource，避免组件离开后继续更新状态。

2.3 Loading、Error、Empty 和 Success

网络页面至少要处理加载中、失败、空数据和成功四类状态。若只写成功界面，后端未启动时就会出现空白或不可理解异常。ResearchFlow 为无法读取运行、操作失败和加载中提供独立展示。

3. 为什么不能只使用 SSE

SSE 适合服务器单向推送进度，但新打开的页面没有此前事件，也不应该依赖一条长期连接恢复整份报告。REST 读取稳定快照，SSE 降低等待期间的刷新成本，两者承担不同职责。

收到终态事件后，前端重新读取运行、计划、材料和度量，而不是仅凭事件消息拼出最终页面。这保证展示结果与后端已经提交的状态一致。

4. Markdown 和公式怎样渲染

LLM 返回 Markdown 字符串
→ 规范化常见模型格式差异
→ react-markdown 生成 React 元素
→ remark-gfm 处理表格等 GFM 语法
→ remark-math 识别行内与块级公式
→ rehype-katex + KaTeX CSS 生成可读公式

research-report.tsx 还为标题、列表、表格、代码块和外部链接定义统一样式。规范化只修正常见的模型输出差异，例如 \(...\)、\[...\] 和紧邻中文的加粗标记，不改写报告含义，也跳过代码围栏。

4.1 Markdown、GFM 和 AST

  • Markdown是用纯文本符号表达标题、列表、强调和链接的标记语言；
  • GFM是 GitHub Flavored Markdown，增加表格、删除线和任务列表等扩展；
  • AST是 Abstract Syntax Tree，抽象语法树，表示解析后的结构而不是原始字符。
"**证据**" → strong 节点 → React <strong> → 浏览器加粗

若星号与中文标点或空格组合不符合解析器规则，可能仍被当普通字符。项目先规范化已知模型格式差异，再交给标准解析插件。

4.2 LaTeX 和 KaTeX

LaTeX 是排版系统，数学公式有专门语法；KaTeX 是在 Web 页面快速渲染一部分 LaTeX 数学语法的库。remark-math 负责识别数学节点，rehype-katex 把节点转换成 KaTeX HTML。

行内：$E = mc^2$
块级：$$\operatorname{MRR}=\frac{1}{N}\sum_{i=1}^{N}\frac{1}{rank_i}$$

公式生成失败可能是分隔符、转义或 KaTeX 不支持的命令问题，不是 Markdown 所有文本都天然能成为公式。

5. 为什么不直接插入模型生成的 HTML

研究报告来自外部模型和网页材料，应当视为不可信文本。项目让 Markdown 解析器创建受控 React 元素，没有启用原始 HTML 解析；外部链接统一在新页面打开并设置 noopener 与 noreferrer。这减少脚本注入和页面结构被任意改写的风险。

这不等于整个应用自动安全：API 鉴权、上传限制、CORS、Secret 和供应商数据政策仍由后端与部署配置负责。

5.1 SSR、CSR 和 Hydration

  • SSR（Server-Side Rendering）在服务器生成初始 HTML；
  • CSR（Client-Side Rendering）在浏览器运行 JavaScript 更新界面；
  • Hydration让浏览器端 React 接管服务器生成的 HTML并附加交互。

ResearchFlow 的核心交互页面是 Client Component，需要浏览器 state、点击事件和 EventSource。Next.js 仍负责路由、开发和生产构建。

6. 可访问性和响应式设计

语义化标题、按钮文本、表格结构和键盘可操作性有助于屏幕阅读器与自动化测试。响应式布局通过 CSS 在窄屏改为单列，避免固定宽度让内容溢出。视觉好看不能替代可访问的语义。

7. 怎样验证这一层

组件测试检查中文加粗、GFM 表格、行内公式和块级公式是否产生预期 HTML；浏览器 E2E 从创建任务开始，检查报告、度量、刷新恢复和历史管理。前者快速定位渲染规则，后者证明真实页面路径能够协作。

8. Server Component 与 Client Component 怎样划分

Server Component 默认在服务器渲染，适合不需要浏览器状态和事件的内容；Client Component 使用 "use client"，可以访问 useState、useEffect、EventSource 和文件选择。ResearchFlow 的交互页面需要大量客户端能力。划分过大增加浏览器 JavaScript，划分过碎则增加数据与组件边界复杂度。

9. Hydration Mismatch 为什么出现

服务器生成的初始 HTML 与浏览器第一次渲染结果不同，会产生 Hydration Mismatch。例如渲染时直接读取当前时间、随机数或仅浏览器存在的对象。需要把客户端专属逻辑放进 Effect，或确保初始值在两侧一致。当前 API 数据主要在客户端加载，避免服务器预渲染时访问本地后端。

10. 为什么 SSE 回调不能随意使用旧 State

JavaScript 闭包会捕获创建回调时的变量值，长连接回调可能拿到旧 sequence 或旧列表，称为 stale closure。项目把事件合并逻辑做成纯函数并使用当前最大序号建立连接。复杂状态继续增长时可使用函数式 setState、Reducer 或 Ref 明确维护最新游标。

11. 列表渲染为什么需要稳定 key

React 用 key 判断元素是新增、删除还是同一个对象。事件、来源和证据应使用稳定 ID，而不是数组下标；否则排序或插入后可能复用错误 DOM 与组件状态。稳定领域 ID 同时帮助测试定位元素和前端去重。

12. 大报告会带来什么性能问题

Markdown 解析、KaTeX 渲染和大量 DOM 都在浏览器消耗 CPU 与内存；频繁 SSE 更新若每次重新渲染整页也会放大开销。当前报告上限较小且只在相关事件后刷新。规模扩大时可拆分组件、记忆化稳定内容、虚拟化超长列表，并对报告大小和公式复杂度设限。

13. 可访问性不只是加 aria-label

语义标题让屏幕阅读器理解结构；按钮需要明确名称和禁用状态；错误提示应可被辅助技术感知；对话框要管理焦点、Escape 和焦点回归；颜色不能是唯一状态信号；表格应有表头。键盘完成创建、重命名、归档和删除，是比视觉截图更实际的检查。

14. 前端如何处理竞态请求

用户快速切换 Run 或组件卸载时，旧请求可能晚于新请求返回并覆盖状态。简单页面可在 Effect 清理时标记忽略；复杂场景使用 AbortController 取消 fetch，并在写状态前核对 runId。EventSource 也必须随 runId 变化关闭旧连接。

面试表达：前端采用“REST 快照 + SSE 增量”的状态同步方式，以 SQLite 持久状态为真相来源；报告通过受控 Markdown AST 管线渲染 GFM 与 KaTeX，没有直接执行模型生成的 HTML。实现还需要关注水合一致性、闭包旧状态、稳定 key、异步竞态、长报告性能和键盘可访问性。
