Lesson 0005 · 约 50 分钟

网页与本地资料怎样穿过 LangGraph

学完后，你应该能解释节点、状态、适配器、来源、证据和持久化更新怎样协作。

先记结论：LangGraph 负责工作流内部编排，但产品对外只暴露 ResearchFlow 自己的领域对象和事件。

先分清：工作流、Agent 和 LangGraph

工作流是一组步骤及其流转规则；Agent通常让模型根据当前状态自主选择下一步或工具；LangGraph是表达有状态节点和边的编排框架，既能实现固定工作流，也能实现更自主的 Agent。

ResearchFlow 当前是确定性的六节点图：代码决定节点顺序，LLM 在节点内部负责规划、理解和写作。它不是让模型无限自主循环调用工具的 ReAct Agent。ReAct 来自 Reasoning and Acting，指模型交替进行推理、选择行动、观察工具结果，再决定下一步。固定流程更容易控制成本、验证证据关系和定位失败。

0.1 Agent 到底是什么

在 AI 应用中，Agent 通常指一个由模型参与决策、能够观察当前状态、选择动作或工具，并根据结果继续推进目标的系统。它不是“只要调用了 LLM 就是 Agent”。

观察当前状态 → 决定下一步 → 调用工具 → 接收结果 → 再决定

自主性越高，能适应的情况越多，但成本、循环次数和行为也更难预测。ResearchFlow 把研究任务拆成固定节点，让模型只在需要语义判断的地方工作，是“受控工作流”取向。

0.2 LangGraph 是什么，不是什么

LangGraph 是用于构建有状态工作流与 Agent 的低层编排框架。Graph 表示“步骤怎样连接”，State 表示“步骤之间传递什么”。它不提供模型本身，不替项目搜索网页，也不会自动设计 Prompt。

ResearchFlow 直接使用 LangGraph 的 StateGraph，没有要求 LangChain 替它调用模型；LLM、搜索和 Embedding 都由项目自己的接口适配。

0.3 图的基本术语

术语通用含义项目对应
Node 节点执行一段工作并返回状态更新planning、searching、reading 等方法
Edge 边规定一个节点之后到哪里planning → searching
State 状态节点共享的一次执行数据目标、计划、来源、证据、报告
START / END图的入口和出口开始规划、检查后结束
Conditional Edge按状态选择分支当前主图未使用

0.4 StateGraph 怎样被构建

builder = StateGraph(_ResearchState)
builder.add_node("planning", self._planning)
builder.add_node("searching", self._searching)
builder.add_edge(START, "planning")
builder.add_edge("planning", "searching")
...
builder.add_edge("checking", END)
self._graph = builder.compile()

TypedDict 描述 State 可包含哪些键，节点读取已有字段并返回本节点产生的字段。compile() 把图定义变成可以执行的对象。当前所有边固定，因此每次成功运行都经过相同顺序。

1. 六个节点

规划→搜索→阅读→证据→写作→检查

规划节点生成研究问题和英文网页检索词；搜索节点创建 ResearchTask；阅读节点联合取得 Exa 网页和用户所选文档片段并转换成 Source；证据节点把原文关联到问题并形成 Claim；写作节点生成报告与可追溯章节；检查节点做确定性关联检查。

节点主要输入主要输出是否调用外部服务
planninggoalResearchPlanLLM
searchingplan、document_ids搜索结果、本地命中、ResearchTaskExa、Embedding
reading搜索结果和本地命中Source、模型可读文档读取 Provider 内容
extracting问题与文档Evidence、ClaimLLM
writing计划、来源和证据Markdown 报告LLM
checking全部材料和报告CitationAudit、最终结果否，确定性代码

1.1 为什么搜索节点是逐问题执行

计划中的每个 ResearchQuestion 有自己的查询。节点逐个调用网页搜索和本地检索，再把结果关联到对应 ResearchTask。这样报告可以追溯“哪个问题触发了哪个检索”，而不是得到一堆无法归属的网页。

当前实现没有并行发出所有查询，因此更容易遵守外部额度，但总耗时可能更长。未来并行化要同时考虑限流、失败隔离和结果顺序，不能只把循环换成 gather。

2. 为什么问题和检索词分开

字段服务对象示例
question用户与报告如何评估 AI 编程工具的真实开发体验？
search_query通用 Web Search APIdeveloper experience AI coding assistant

研究问题表达“想知道什么”，检索词表达“怎样向特定搜索系统提问”。

3. 四个深接口

LangGraphResearchWorkflow
├─ LLMClient
├─ SearchProvider
├─ WebPageReader
└─ KnowledgeRetriever
   └─ EmbeddingClient

测试注入 Fake，真实运行注入 OpenAI-compatible LLM、Exa、Gemini Embedding 和本地检索实现。Embedding 适配器按模型版本区分文档与查询用途，再以余弦相似度排列 SQLite 中的片段向量。节点不需要知道 HTTP 参数、任务指令、上传存储、分块算法或供应商响应结构；这些接口和 ResearchFlow DTO 隔离细节。

4. Source 和 Evidence 的区别

  • Source 是某次运行实际读过的网页或本地片段；
  • Evidence 是来源短原文与解释，并关联 Source 和 Research Question；
  • 有 Source 不代表它支持结论，建立 Evidence 关联后材料才进入证据链。

5. 为什么 Graph 不直接写数据库

工作流把节点状态转换成 ResearchWorkflowUpdate，Application 统一保存材料和事件。未来更换编排框架时，API 无需跟着改变。

5.1 astream 和增量更新

工作流使用 graph.astream(..., stream_mode="updates") 异步执行。每个节点完成后，LangGraph 产出该节点的状态更新；项目再把更新转换成自己的 ResearchWorkflowUpdate。Application 保存后才生成面向前端的领域事件。

LangGraph 节点更新
  → ResearchWorkflowUpdate
  → Application 持久化
  → ResearchEvent
  → SSE
  → React 页面

LangGraph 的内部流不直接暴露给浏览器，因此框架升级、节点改名或 State 字段变化不会自动成为公共 API 破坏。

5.2 错误怎样离开图

Embedding、LLM 和网页服务错误都有稳定 code 与公开 message。图执行捕获这些预期集成错误并产出失败更新；Application 再把运行和失败事件持久化。未知异常由应用层记录详细日志，对用户只返回安全消息。

这种边界让“模型服务超时”和“Python 程序存在 bug”在日志和错误码上可区分。

6. 当前怎样检查引用

当前实现要求每条 Claim 至少关联一条已有 Evidence、每条 Evidence 指向已有 Source，并检查报告的主张小节包含对应来源定位。网页使用可点击 URL，本地资料使用文件名与页码或行号。界面显示主张覆盖率和来源类型计数；DOI、OCR、卷期和被引量等能力仍不在当前范围。

7. Graph State 不等于数据库状态

Graph State 是一次执行期间在节点间传递的工作内存；SQLite 保存的是用户刷新、进程重启后仍需存在的产品状态。当前 LangGraph 没有配置 Checkpointer，恢复策略是将重启时未完成的运行标记失败并允许重试，而不是从某个图节点断点续跑。

7.1 Checkpointer 是什么

LangGraph Checkpointer 可以在图步骤之间保存 State 快照，用于中断恢复、人机协作或时间旅行。它与 ResearchFlow 自己的 Repository 不是同一个抽象：前者保存编排执行状态，后者保存用户可见的产品实体。

当前流程只有几分钟、允许失败后新建一次重试，因此没有引入双重持久化。若以后要求从写作节点精确恢复，才需要设计 Checkpointer、幂等外部调用和产品状态之间的一致性。

7.2 为什么用了 LangGraph 仍不是“自动获得可靠性”

  • 框架不会自动保证外部 LLM 和搜索成功；
  • 未配置 Checkpointer 就没有节点级断点恢复；
  • 节点副作用若不幂等，重放可能重复调用或重复写入；
  • State 类型只约束程序结构，不证明研究内容正确；
  • 可靠性仍需要事务、错误映射、限额、日志和测试。

8. 关联关系总结

六个 StateGraph 节点用固定边按顺序连接；Fake 与真实搜索/本地检索实现遵守相同接口，因此测试无需访问互联网。数据关系从 Research Question 开始，经 ResearchTask 记录检索，再由 Source 保存实际读取的网页或本地片段，Evidence 把原文关联回问题和来源，Claim 最后把报告中的关键陈述关联到一条或多条 Evidence。

面试表达：项目用 LangGraph 表达固定、有状态、可观察的研究流程，而不是把全部控制权交给开放式 Agent；框架状态与 SQLite 产品状态分离，工作流通过领域更新向应用层报告结果。
