Lesson 0005 · 约 20 分钟

一次网页研究怎样穿过 LangGraph

学完后，你应该能解释节点、状态、适配器、来源、证据和持久化更新怎样协作。

先记结论：LangGraph 负责工作流内部编排，但产品对外只暴露 ResearchFlow 自己的领域对象和事件。

1. 六个节点

规划→搜索→阅读→证据→写作→检查

规划节点生成研究问题和英文检索词；搜索节点创建 ResearchTask；阅读节点保存 Source；证据节点把网页片段关联到问题；写作节点生成报告；检查节点做确定性关联检查。

2. 为什么问题和检索词分开

字段服务对象示例
question用户与报告如何评估 AI 编程工具的真实开发体验？
search_query通用 Web Search APIdeveloper experience AI coding assistant

研究问题表达“想知道什么”，检索词表达“怎样向特定搜索系统提问”。

3. 三个深接口

LangGraphResearchWorkflow
├─ LLMClient
├─ SearchProvider
└─ WebPageReader

测试注入 Fake，真实运行注入 OpenAI-compatible 和 Exa 实现。节点不需要知道 HTTP 参数、重试或 Exa 响应结构；SearchResult 和 WebDocument 负责隔离供应商。

4. Source 和 Evidence 的区别

  • Source 是实际读过的网页；
  • Evidence 是网页短原文与解释，并关联 Source 和 Research Question；
  • 有 Source 不代表它支持结论，建立 Evidence 关联后材料才进入证据链。

5. 为什么 Graph 不直接写数据库

工作流把节点状态转换成 ResearchWorkflowUpdate，Application 统一保存材料和事件。未来更换编排框架时，API 无需跟着改变。

6. 当前检查不是完整引用验证

M2 只确认 Evidence 指向已有 Source，并检查报告包含来源链接。M3 将加入来源分类与元数据、Claim—Evidence 关系、来源质量控制和引用覆盖检查。

7. 关联关系总结

六个 StateGraph 节点用固定边按顺序连接；FakeSearchProvider 与真实搜索实现遵守相同接口，因此测试无需访问互联网。数据关系从 Research Question 开始，经 ResearchTask 记录检索，再由 Source 保存实际读取的网页，最后由 Evidence 把原文片段关联回问题和来源。
