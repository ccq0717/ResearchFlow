Lesson 0005 · 约 20 分钟

网页与本地资料怎样穿过 LangGraph

学完后，你应该能解释节点、状态、适配器、来源、证据和持久化更新怎样协作。

先记结论：LangGraph 负责工作流内部编排，但产品对外只暴露 ResearchFlow 自己的领域对象和事件。

先分清：工作流、Agent 和 LangGraph

工作流是一组步骤及其流转规则；Agent通常让模型根据当前状态自主选择下一步或工具；LangGraph是表达有状态节点和边的编排框架，既能实现固定工作流，也能实现更自主的 Agent。

ResearchFlow 当前是确定性的六节点图：代码决定节点顺序，LLM 在节点内部负责规划、理解和写作。它不是让模型无限自主循环调用工具的 ReAct Agent。固定流程更容易控制成本、验证证据关系和定位失败。

1. 六个节点

规划→搜索→阅读→证据→写作→检查

规划节点生成研究问题和英文网页检索词；搜索节点创建 ResearchTask；阅读节点联合取得 Exa 网页和用户所选文档片段并转换成 Source；证据节点把原文关联到问题并形成 Claim；写作节点生成报告与可追溯章节；检查节点做确定性关联检查。

2. 为什么问题和检索词分开

字段服务对象示例
question用户与报告如何评估 AI 编程工具的真实开发体验？
search_query通用 Web Search APIdeveloper experience AI coding assistant

研究问题表达“想知道什么”，检索词表达“怎样向特定搜索系统提问”。

3. 四个深接口

LangGraphResearchWorkflow
├─ LLMClient
├─ SearchProvider
├─ WebPageReader
└─ KnowledgeRetriever
   └─ EmbeddingClient

测试注入 Fake，真实运行注入 OpenAI-compatible LLM、Exa、Gemini Embedding 和本地检索实现。Embedding 适配器按模型版本区分文档与查询用途，再以余弦相似度排列 SQLite 中的片段向量。节点不需要知道 HTTP 参数、任务指令、上传存储、分块算法或供应商响应结构；这些接口和 ResearchFlow DTO 隔离细节。

4. Source 和 Evidence 的区别

  • Source 是某次运行实际读过的网页或本地片段；
  • Evidence 是来源短原文与解释，并关联 Source 和 Research Question；
  • 有 Source 不代表它支持结论，建立 Evidence 关联后材料才进入证据链。

5. 为什么 Graph 不直接写数据库

工作流把节点状态转换成 ResearchWorkflowUpdate，Application 统一保存材料和事件。未来更换编排框架时，API 无需跟着改变。

6. 当前怎样检查引用

当前实现要求每条 Claim 至少关联一条已有 Evidence、每条 Evidence 指向已有 Source，并检查报告的主张小节包含对应来源定位。网页使用可点击 URL，本地资料使用文件名与页码或行号。界面显示主张覆盖率和来源类型计数；DOI、OCR、卷期和被引量等能力仍不在当前范围。

7. Graph State 不等于数据库状态

Graph State 是一次执行期间在节点间传递的工作内存；SQLite 保存的是用户刷新、进程重启后仍需存在的产品状态。当前 LangGraph 没有配置 Checkpointer，恢复策略是将重启时未完成的运行标记失败并允许重试，而不是从某个图节点断点续跑。

8. 关联关系总结

六个 StateGraph 节点用固定边按顺序连接；Fake 与真实搜索/本地检索实现遵守相同接口，因此测试无需访问互联网。数据关系从 Research Question 开始，经 ResearchTask 记录检索，再由 Source 保存实际读取的网页或本地片段，Evidence 把原文关联回问题和来源，Claim 最后把报告中的关键陈述关联到一条或多条 Evidence。

面试表达：项目用 LangGraph 表达固定、有状态、可观察的研究流程，而不是把全部控制权交给开放式 Agent；框架状态与 SQLite 产品状态分离，工作流通过领域更新向应用层报告结果。
