async、await 和后台任务到底在做什么

研究流程会等待多个网络服务，若逐步阻塞线程，API 就很难同时响应查看状态和取消请求。

简短回答：async 定义协程，await 在等待 I/O 时把执行权交回事件循环，create_task 把协程安排为可独立推进的任务。它们提高等待型工作的并发能力，不会自动让 CPU 计算变快。

0. I/O 和 CPU 工作是什么

I/O 是 Input/Output，即输入/输出。网络请求、磁盘和数据库通常要等待外部设备或服务；CPU-bound 工作则主要消耗处理器执行计算，例如大型矩阵计算或压缩。

ResearchFlow 大部分长时间花在等待 LLM、搜索和 Embedding 的网络响应，因此适合异步 I/O。余弦扫描规模很小时 CPU 开销较低；若变成百万向量计算，async 不会自动解决性能问题。

0.1 并发和并行

概念含义比喻
Concurrency 并发多个任务在同一时间段内交替推进一个厨师等烤箱时去切菜
Parallelism 并行多个任务在同一时刻真正执行多个厨师同时工作

单线程事件循环能实现并发 I/O，不一定实现 CPU 并行。多线程、多进程和异步是不同工具。

1. 同步等待和异步等待

同步：发出请求 ───────── 等待 ───────── 得到结果
异步：发出请求 ── await ── 事件循环处理其他连接 ── 恢复

LLM、Exa、Embedding 和 SQLite 都属于 I/O 等待。ResearchFlow 使用 HTTPX 异步客户端、SQLAlchemy AsyncSession 和 aiosqlite，使等待期间同一个进程还能处理其他 HTTP 请求。

2. 三个容易混淆的概念

概念含义
协程 Coroutine一次可暂停、可恢复的异步计算；调用 async def 只得到协程对象。
任务 Task事件循环已经安排执行的协程，可查询完成状态或取消。
事件循环 Event Loop在任务就绪时推进它，在任务等待 I/O 时切换到其他任务。

await 不是创建线程，也不等于“所有代码并行”。如果在协程里执行很长的纯 CPU 循环且从不让出执行权，事件循环仍会被卡住。

2.1 async def 调用后为什么还没执行

async def fetch():
    return "done"

coroutine = fetch()       # 只创建协程对象
result = await coroutine  # 当前任务等待它完成
task = asyncio.create_task(fetch())  # 安排它独立推进

漏写 await 可能得到“coroutine was never awaited”警告。把所有调用都改成 create_task 也不对：需要返回值和顺序依赖时通常应该 await。

2.2 await 时事件循环做什么

当底层异步 I/O 尚未就绪，当前 Task 暂停，事件循环运行其他已就绪 Task；网络通知结果到达后，原 Task 从 await 之后恢复。切换发生在明确可等待点，比操作系统抢占线程更协作式。

2.3 阻塞代码为什么危险

time.sleep()、同步网络请求或大量 CPU 循环会占住事件循环线程。项目使用 await asyncio.sleep() 做 SSE 等待，并用 asyncio.to_thread 包装文件读写和 PDF 解析，使这些同步操作不直接堵住主事件循环。

3. 创建研究为什么立即返回

ResearchRunApplication.create_run 先把 queued 记录写入数据库，再用 asyncio.create_task 启动工作流，最后把运行记录返回给路由。浏览器很快得到任务 ID，随后通过 SSE 观察后台进展。

POST /research-runs
  → 保存 queued
  → create_task(_execute_workflow(...))
  → 立即返回 run_id
  → 后台持续保存进度和事件

4. 并发不等于无限并发

每个真实研究都会消耗模型额度、搜索请求和内存。应用用任务表统计进程内活跃运行，并设置同时运行数与每日运行数上限。锁保护“检查上限 + 创建任务”这一段，避免两个请求同时通过检查造成超额。

这些限制适合单进程在线 Demo。若部署多个后端实例，内存任务表和锁无法跨进程协调，需要队列、共享数据库锁或专门任务系统。

4.1 Lock 和 Semaphore 有什么区别

Lock（锁）让同一时刻只有一个任务进入临界区，适合保护“检查配额并创建”的组合操作。Semaphore（信号量）允许最多 N 个任务进入，常用于控制外部请求并发。当前应用以活跃 Task 计数和 Lock 保证创建上限。

4.2 Race Condition 是什么

Race Condition（竞态条件）表示结果依赖多个任务不可控的执行顺序。如果两个创建请求都先看到“当前只有 1 个运行”，然后都创建，就可能突破上限。把检查与创建放在同一锁内，使它们对其他创建请求表现为一个整体。

5. 取消为什么没有想象中简单

task.cancel() 会请求任务在下一个可取消点抛出 CancelledError，不是立刻杀死代码。若恰好正在保存一个完成节点，半途取消可能让“事件已写但状态未写”之类的不一致出现。

项目用 asyncio.shield 保护单次工作流更新的持久化：外部取消到达后，先等这次保存完整结束，再把取消继续向上传递。数据库 Session 的回滚和关闭也受到相同保护。

6. 进程退出会怎样

后台 Task 只存在于当前 Python 进程，重启后不能恢复执行。应用启动时会扫描未结束运行并标记为中断失败；用户可以重试。这是“可解释失败”，不是持久任务队列。生产级长任务可进一步使用持久队列和 worker。

7. Exception、CancelledError 和 finally

普通业务异常表示操作失败；取消通过 CancelledError 在 await 点传播。资源释放应放在 finally 或异步上下文管理器中，确保成功、失败和取消都能关闭 HTTP Client、Session 或文件。

取消通常应在完成必要清理后继续向上传播，不能悄悄吞掉，否则调用方会误以为任务正常完成。

8. gather、TaskGroup 和顺序 await

  • 顺序 await：后一步依赖前一步，或要严格控制外部额度；
  • gather：同时等待多个已知异步操作，需要设计部分失败行为；
  • TaskGroup：结构化并发，让一组子任务的生命周期属于同一代码块。

前端会并行读取多个独立 REST 快照；后端研究问题当前顺序搜索。并行化不是语法替换，还会改变限流、成本和错误传播。

9. 什么时候需要真正的任务队列

当任务必须跨进程恢复、需要多个 worker、需要延迟/优先级调度或运行时间很长时，可使用持久任务队列。队列会保存待执行消息，worker 独立消费；同时必须设计幂等、重试、死信和状态同步。

当前 Demo 选择进程内 Task，是因为单实例、低并发、运行时间有限且失败后允许显式重试。

10. 常见误区

  • “async 比同步永远快”：它主要提高 I/O 等待时的吞吐，不减少外部服务自身延迟。
  • “调用 async 函数就开始执行”：还要 await 或创建 Task。
  • “取消会回滚一切”：取消只是一种异常传播，必须显式设计一致性和清理。
  • “单进程锁能管多台服务器”：不能，它只保护当前事件循环内的共享状态。

11. Event Loop 一轮做什么

事件循环维护就绪回调、计时器和 I/O 完成通知。协程运行到 await 一个尚未完成的操作时暂停，把控制权交回；I/O 就绪后对应 Task 再进入可运行队列。协作式调度要求代码主动 await，长时间纯计算不会被自动抢占。

12. GIL 与 asyncio 有什么关系

CPython 的 GIL（Global Interpreter Lock，全局解释器锁）限制同一进程中多个线程同时执行 Python 字节码。asyncio 主要在单线程中交替等待 I/O，本来就不依赖多线程并行，因此适合网络型工作。CPU 密集任务需要进程池、原生扩展或独立 Worker；to_thread 主要避免阻塞事件循环，不保证 Python 计算并行加速。

13. Task 和 Future 有什么区别

Future 表示未来会得到一个结果的占位对象；Task 是包装协程并由事件循环推进的一种 Future。通常应用代码创建 Task、await 协程，底层库用 Future 连接 I/O 完成通知。创建 Task 后若不保留引用，异常和生命周期会难以管理；项目用字典保存 Task→Run ID。

14. Structured Concurrency 为什么重要

结构化并发要求子任务生命周期受一个明确作用域管理：离开作用域前等待完成或统一取消。Python TaskGroup 就体现这一点。项目的研究 Task 有应用级注册、shutdown 统一取消；若在搜索节点并行多个问题，TaskGroup 比裸 create_task 更容易正确传播失败。

15. 取消是请求，不是强制终止

task.cancel()安排 CancelledError 在下一个可取消 await 点抛出；同步 CPU 循环或不配合取消的库不会立刻停止。清理代码应使用 finally，并避免吞掉 CancelledError。外部 HTTP 请求是否真正停止还取决于客户端能否关闭连接，供应商可能已经开始计费。

16. 异步数据库 Session 为什么不能跨 Task 随意共享

Session 包含事务和对象状态，不适合作为全局可并发对象。项目每个 Repository 方法通过 session factory 创建独立 Session，并在上下文结束时关闭。并行任务若共享同一 Session，可能交叉提交、状态冲突或触发驱动限制。

面试表达：ResearchFlow 把耗时研究作为进程内 asyncio Task 运行，让创建接口立即返回并通过 SSE 汇报进度。事件循环适合 LLM、搜索与数据库的 I/O 等待，不解决 CPU 密集计算；Task 被显式注册和统一取消，持久化更新用 shield 保护，并明确多实例需要持久任务队列。
