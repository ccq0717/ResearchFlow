怎样知道 RAG 真的检索对了

“用了 Embedding”只说明技术链路存在。要判断效果，必须把检索质量与最终报告质量拆开测量。

简短回答：先准备查询及其相关片段标注，再用 Recall@K、MRR 等指标评估检索；随后评估报告是否忠于证据、引用是否完整、是否真正回答问题。ResearchFlow 已有小型检索基准和端到端验收，但样本量不足以代表普遍质量。

1. RAG 的离线和在线阶段

离线/入库：文档 → 解析 → 分块 → 文档向量 → 保存
在线/查询：问题 → 查询向量 → 相似度排序 → Top-K → 交给 LLM

“离线”不是一定要断网，而是指与某次用户查询无关、可提前完成的索引阶段。ResearchFlow 在上传或重新处理文档时完成入库，在研究运行的阅读节点进行查询。

2. 稀疏、稠密和混合检索

方法优势局限
词法/稀疏检索（如 BM25）精确关键词、编号和专有名词表现好，可解释不易识别换一种说法的同义语义
Embedding/稠密检索能按语义相似找到不同表述可能忽略精确词，依赖模型和向量空间
混合检索融合两类优势需要归一化、融合权重和更多评测

当前项目直接使用稠密检索，没有保留旧的简单词法模式。对小型作品集，这让主路径清晰；如果真实数据出现大量版本号、API 名或论文编号，可通过基准证明是否需要混合检索。

3. 分块如何影响结果

  • 块太大：一个向量混合多个主题，返回上下文噪声高；
  • 块太小：事实被截断，命中片段缺少解释所需上下文；
  • 无重叠：跨边界句子可能丢失；重叠过多：结果容易返回重复文本。

合理参数取决于文档结构和查询，不能只凭经验声称最佳。可分别尝试字符、段落、标题层级或语义分块，再在同一查询集上比较。

4. Top-K、重排和上下文

第一阶段向量检索强调快速召回；可选的 reranker 会同时阅读查询与候选片段，进行更精细但更昂贵的相关性排序。最后只把重排后的少量片段交给 LLM。

ResearchFlow 当前对 SQLite 中的候选逐个算余弦相似度并取 Top-K，没有 reranker。数据量小时实现简单、可观察；是否增加重排应由失败案例和指标驱动。

5. 三个常见检索指标

指标直觉适合回答
Recall@K所有相关片段中，有多少进入前 K关键资料有没有被漏掉
Precision@K前 K 个结果中，有多少真的相关交给模型的噪声有多少
MRR第一个相关结果排名倒数的平均值最先看到正确结果有多快

例如某查询第一个相关片段排第 2，倒数排名是 1/2。多个查询取平均得到 MRR。指标需要“哪个片段相关”的人工或可信标注，没有 qrels 的漂亮数字没有依据。

5.1 qrels 是什么

qrels 是 query relevance judgments，即“查询—文档相关性判断”。它记录对每个查询，哪些文档相关以及可能的相关等级。评测程序把检索排名与 qrels 对比。

query_1 → doc_A: relevant
        → doc_B: not relevant
        → doc_C: highly relevant

标注本身可能主观，应定义判断标准并由领域人员抽查。没有可信标签，就无法知道系统漏了什么。

5.2 Hit Rate、MRR 和 nDCG

指标关注点局限
Hit Rate@K前 K 是否至少出现一个相关结果不关心第几名和其他相关结果
MRR第一个相关结果排名忽略后续相关结果
nDCG多个结果的分级相关性和位置计算和标注更复杂

当前小基准使用 Top-1 Accuracy 和 MRR@3，足以捕捉排序被破坏，不代表它们是所有场景的最佳指标。

5.3 Offline 和 Online Evaluation

Offline Evaluation 在固定语料、查询和标签上重复比较方案；Online Evaluation 观察真实用户行为和反馈。作品集没有足够真实流量，因此重点是离线回归和人工真实任务审阅。

6. 当前基准能说明什么

项目的固定小型基准包含 3 个查询，在当前样本上 Top-1 命中率和 MRR 都为 1.0。它可以防止接口、用途指令或排序逻辑被改坏，是回归测试；只有 3 条数据，不能据此宣称对任意论文和问题都有 100% 检索准确率。

7. 最终报告还要单独评估

  • 忠实性：结论是否能由给定 Evidence 支持；
  • 引用覆盖：可核验 Claim 中有多少关联了 Evidence；
  • 完整性：研究问题是否都得到回应，证据不足是否说明；
  • 有用性：结构、建议和交付物是否满足用户目标。

引用覆盖为 100% 只表示 Claim 都有引用关系，不证明来源权威、原文真的蕴含结论或报告整体优秀。确定性检查、人工审阅和模型评审各自能覆盖不同风险。

7.1 Faithfulness 和 Answer Relevance

  • Faithfulness（忠实性）：答案陈述是否由检索上下文支持；
  • Answer Relevance（回答相关性）：答案是否真正回应用户问题；
  • Context Relevance（上下文相关性）：交给模型的片段是否相关且少噪声；
  • Context Recall（上下文召回）：回答所需信息是否被检索出来。

忠实但没有回答问题的报告仍然无用；相关但没有证据的报告风险也高。

7.2 LLM-as-a-Judge 的边界

可用模型按 Rubric 给报告打分，称为 LLM-as-a-Judge。它比纯字符串指标更能处理自然语言，但会受评审模型偏差、顺序、提示和自身知识影响。重要结论应配合人工抽查，并保存评审标准与版本。

7.3 建立评测集的步骤

  1. 从真实目标收集有代表性的查询；
  2. 固定文档版本并标注相关片段；
  3. 定义检索与报告 Rubric；
  4. 记录模型、分块、K 值和运行配置；
  5. 改动前后在同一集合比较；
  6. 分析每个失败案例，而不只看平均分。

8. Ablation 是什么

Ablation Study（消融实验）逐一移除或替换组件，观察质量变化。例如比较无 RAG、Embedding RAG、加入 reranker 三种方案，才能说明某个组件是否真正贡献效果。

只展示最终系统一次成功，不能证明每项复杂技术都有必要。

9. 从失败现象定位环节

现象优先检查
正确片段根本没返回解析、分块、查询表达、Embedding、K 值
返回很多相似但无用片段块大小、重复内容、混合检索或 rerank
片段正确但答案编造证据提取 Prompt、上下文组织、生成约束
答案正确但无法核验页码/行号、Source—Evidence—Claim 关联

10. Recall@K 的公式和局限

对一个查询，Recall@K = 前 K 个结果中相关文档数量 ÷ 全部相关文档数量。若共有 4 个相关 Chunk，Top-5 找到 3 个，Recall@5=0.75。它关心漏掉多少，不关心相关结果在第 1 还是第 5，也不惩罚大量无关结果，因此要和排序或 Precision 指标一起看。

11. MRR 为什么只看第一个相关结果

每个查询的 Reciprocal Rank 是第一个相关结果名次的倒数：第 1 为 1，第 2 为 0.5，第 5 为 0.2；MRR 是多个查询平均。它适合用户只需要快速看到一个正确结果的场景，但一条研究结论可能需要多份证据，此时 MRR 会忽略后续相关结果。

12. nDCG 怎样处理分级相关性

DCG 对高相关结果给更高 gain，并按排名位置对靠后结果折损；再除以理想排序的 IDCG 得到 0–1 的 nDCG。它可以把“完全相关、部分相关、不相关”区别开，比二元命中更贴近研究材料质量，但标注成本和主观性更高。

13. 评测单位应是 Document 还是 Chunk

Chunk-level 能精确判断交给模型的片段是否包含答案，但同一文档相邻块会让指标敏感；Document-level 更稳定，却可能把命中无关章节也算成功。项目本地检索真正返回 Chunk，因此排序回归应以 Chunk 为主，同时汇总 Document 命中用于理解去重和来源覆盖。

14. 怎样避免 Evaluation Leakage

如果反复根据同一小测试集调整 Prompt、分块和阈值，系统会过拟合评测。应区分开发集和最终测试集，记录每次实验，限制查看保留集，并定期加入真实失败样例。模型预训练可能见过公开问答，也会让某些“无 RAG”答案看似很好，因此要检查证据忠实度。

15. 差异多大才算真实改进

3 个查询从 0.67 变成 1.0 可能只是一个样例变化。更大评测集应报告逐查询差异、置信区间或 bootstrap，并对质量、延迟、成本共同比较。开放生成还需多人盲评和一致性统计。没有样本规模与方差，只报平均分会制造虚假确定性。

16. End-to-End 分数为什么难定位问题

报告差可能来自查询生成、搜索召回、分块、Embedding、证据提取或写作。只给最终报告一个总分无法知道改哪里。项目把计划、任务、来源、Evidence、Claim 和报告分别持久化，就是为了逐层观察；评测也应沿相同结构分解。

面试表达：项目把 RAG 拆成索引、检索、证据和生成分别观察；Recall@K 衡量召回，MRR 强调首个相关结果，nDCG 支持分级排序。当前固定小集只做回归，不代表产品质量；可信改进需要独立测试集、逐例分析、统计不确定性和质量—延迟—成本联合比较。
