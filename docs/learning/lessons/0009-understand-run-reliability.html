Lesson 0009 · 约 20 分钟

后台任务失败后，系统怎样保持状态可信

ResearchFlow 的研究可能运行数分钟。可靠性不是保证永不失败，而是让取消、失败、重启和重试都有明确且可恢复的结果。

先记结论：SQLite 中的 Research Run 是权威状态；内存任务只负责当前执行，事件负责解释状态怎样变化。

1. 创建接口为什么立即返回

FastAPI 先保存 queued 运行和 run.queued 事件，再创建后台 asyncio Task。浏览器马上得到 ID，随后用普通查询和 SSE 观察进度，不需要让一个 POST 请求等待整份报告。

2. 状态与事件为什么同事务终结

完成、失败和取消都通过 ResearchRunOutcome 写入。Repository 在一个事务里同时更新运行终态和追加终结事件，因此前端不会看到“状态已完成，但完成事件还不存在”的半成品。

3. 取消为什么要等待数据库操作

asyncio 取消会在一次 await 处抛出异常，但 SQLite 的提交可能已经在线程中开始。应用会屏蔽这次持久化操作的中途取消，等待提交或回滚结束，再传播取消，避免遗留写锁。

4. 进程重启后发生什么

后台 Task 存在于内存，进程退出后无法继续。下次启动扫描仍为 queued 或 running 的记录，将其标记为 RUN_INTERRUPTED。系统没有把失败误报为继续运行。

5. “恢复”为什么是新运行

当前 LangGraph 没有持久 checkpoint，所以失败运行会创建一个新的第二次运行，并保存 retry_of 与 attempt；原失败记录和中间材料保留。一次上限防止错误配置持续消耗额度。

行为当前语义
刷新页面恢复已持久化的同一运行
服务重启遗留运行明确失败
点击重试创建一次有谱系的新运行
断点续跑当前没有实现，也不会假装已经实现

6. 限额和日志解决什么

并发上限保护单实例 SQLite 和外部服务；每日运行上限限制公开 Demo 的费用。JSON 日志只记录请求 ID、路径、状态和耗时，不记录目标正文、文档、密钥或供应商原始响应。

7. 怎样证明可靠性

生命周期测试覆盖完成、取消、重启中断、一次重试和配额；浏览器 E2E 覆盖创建、报告、度量和刷新恢复。备份恢复演练还会运行 SQLite 完整性检查。不同测试分别证明状态机、用户路径和数据可恢复性。

面试表达：项目把持久状态、内存执行和可重放事件分开；失败恢复采用诚实的一次新运行语义，并用事务、限额、结构化日志和端到端测试形成可靠性闭环。
