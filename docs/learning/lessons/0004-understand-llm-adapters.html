Lesson 0004 · 约 18 分钟

真实 LLM 是怎样接入后端的

学完这一课，你应该能解释模型 API、接口、适配器、Fake、结构化输出和环境变量分别解决什么问题。

先记结论：LLM 不是直接“装进网页”。浏览器把研究目标交给后端，后端通过 HTTP 调用模型服务，再把经过校验的研究计划保存到数据库。

1. 当前有两种工作流模式

模式是否联网调用模型用途
simulation否默认演示、低资源运行、没有 API Key 时开发
research是规划、网页检索、证据提取和报告写作

模式由 RESEARCHFLOW_WORKFLOW_MODE 决定。默认值是 simulation，所以拉取仓库后不会意外产生模型费用。

2. 接口和适配器是什么

LLMClient 提供计划生成、证据提取和报告写作三个领域操作。调用方不需要知道 URL、Authorization Header、提示词和厂商 JSON。

研究工作流 → LLMClient → 研究计划
                    ├─ FakeLLMClient
                    └─ OpenAICompatibleLLMClient

适配器是接口的具体实现。Fake 返回固定但合理的数据；远程适配器发送真实 HTTP 请求。两者返回相同的 LLMPlanResult，因此工作流不需要写两套业务逻辑。

3. 为什么测试使用 Fake

  • 不需要 API Key，不产生费用；
  • 不会因网络或供应商故障随机失败；
  • 输出确定，测试可以精确断言问题数量、模型名和 Token 数据；
  • 仍会穿过工作流、数据库和 API，能验证真实业务边界。

Fake 不是“假装测试全部真实能力”。远程 HTTP 格式另有 MockTransport 测试，而真实供应商的线上兼容性仍需在配置服务后单独验证。

4. 什么是结构化输出

普通模型回复是一段自由文本，程序很难稳定地提取字段。ResearchFlow 给模型一个 JSON Schema，要求返回摘要、3～8 个研究问题和交付物。Pydantic 再对返回内容做第二次校验。

{
  "summary": "计划摘要",
  "questions": [
    {
      "question": "要调查什么？",
      "rationale": "为什么要调查？",
      "search_query": "English technical search query"
    }
  ],
  "deliverables": ["最终交付物"]
}

“模型说它会遵守格式”不是保证；只有程序验证通过的数据才会成为 ResearchPlan。

5. 一次真实规划请求经过哪里

网页→FastAPI→Workflow →LLM API→SQLite
  1. 前端 POST 一个研究目标；
  2. 后端创建 Research Run；
  3. 工作流调用 LLMClient.create_research_plan；
  4. 远程服务返回 JSON，Pydantic 校验；
  5. 计划写入 research_plans；
  6. SSE 通知前端，前端再读取计划 API。

6. Base URL、模型名和 API Key

配置含义
Base URL模型服务 API 的根地址，例如包含 /v1
Model供应商识别具体模型的名称
API Key证明调用者权限的秘密凭证；本地兼容服务可能不需要

密钥只放在被 Git 忽略的 .env，不能写进 Python、README、截图或提交记录。前端也绝不能接收模型密钥。

7. 为什么记录耗时和 Token

耗时帮助判断用户等待发生在哪里；Token 是很多模型服务计费和上下文容量的基础单位。research 模式调用模型生成研究计划、提取 Evidence/Claim、撰写报告；网页搜索、正文读取、流程编排和引用结构审计不是模型生成。

运行页按输入、输出 Token 和配置的每百万 Token 单价估算 LLM 费用，不包含 Exa、Embedding 或部署平台费用，也不处理缓存 Token 等供应商特殊折扣。

8. 失败时会发生什么

超时、连接失败、HTTP 错误和格式错误会转换成稳定错误代码。前端得到的是安全、可理解的消息，而不是可能包含内部地址、响应正文或密钥的异常堆栈。Research Run 会进入 failed 终态。

9. 真实研究模式的能力边界

research 模式把模型计划送入网页与本地资料检索，再让模型基于实际 Source 提取证据和写作。引用检查能验证关系完整，但不能自动保证来源质量、语义充分性或事实绝对正确。

10. 三个适配器边界

  • 稳定接口隔离了模型厂商细节，更换兼容服务时不需要修改业务流程。
  • Fake LLM 能确定性验证应用、工作流、持久化和 API 契约，但不能证明真实供应商在线或完全兼容。
  • HTTP 200 只说明服务器成功处理了请求，不保证响应满足业务字段、类型和数量限制，因此仍需 Pydantic 校验。
