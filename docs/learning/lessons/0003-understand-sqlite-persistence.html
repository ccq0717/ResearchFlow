SQLite、SQLAlchemy 和 aiosqlite 分别做什么

学完这一课，你应该能解释为什么 ResearchFlow 不需要启动数据库服务，以及一个研究任务怎样从 Python 对象变成磁盘中的记录。

最重要的结论：我没有为项目安装独立 SQLite 服务。SQLite 是嵌入应用进程的数据库引擎，ResearchFlow 后端直接读写一个数据库文件。

1. SQLite 与 PostgreSQL 的直观区别

SQLitePostgreSQL 等数据库服务器
应用进程直接读写数据库文件应用通过网络连接独立数据库进程
不需要单独启动数据库服务需要安装、启动和维护服务
适合本地、单机和原型适合多用户、并发和生产部署

SQLite 官方将这种模式称为 serverless：这里不是指云函数，而是指没有独立数据库服务器进程。

2. 五层不要混在一起

层ResearchFlow 中的角色
数据库文件var/researchflow.db，真正保存字节
SQLite 引擎理解 SQL 和数据库文件格式，通常随 Python 的 sqlite3 支持一起提供
aiosqlite给同步 SQLite 操作提供适合 async/await 的接口
SQLAlchemy把 Python 类、查询和事务映射到数据库操作
RepositoryResearchFlow 自己定义的数据访问边界，隐藏具体存储细节

Python 官方提供 sqlite3 标准库接口；项目另外安装的是 aiosqlite 异步桥接包和 SQLAlchemy，而不是一个需要常驻运行的 SQLite 服务。

3. 读懂数据库连接地址

sqlite+aiosqlite:///./var/researchflow.db
│      │          └─ 数据库文件路径
│      └──────────── 异步驱动
└─────────────────── 数据库类型

这个地址来自后端配置。三个斜杠后的相对路径以启动后端时的当前目录为基准，所以项目统一要求从仓库根目录启动。

4. 数据库何时出现

后端启动时，main.py 的生命周期函数调用 create_schema(engine)。database.py 随后执行：

await connection.run_sync(Base.metadata.create_all)

如果数据库文件或表不存在，SQLAlchemy 会根据模型创建它们；已经存在时则保留原数据。因此首次启动会自动生成文件，重启后历史记录仍然存在。

5. 当前六张表怎样分工

表保存什么关系
research_runs目标、状态、阶段、进度、报告和时间一个任务一行
research_plans计划摘要、研究问题、交付物和模型调用元数据LLM 模式下一个任务至多一行
research_events事件类型、序号、消息、阶段和进度一个任务对应多行
research_tasks研究问题对应的检索词和状态一个任务对应多个检索任务
research_sources已读取网页的标题、URL 和摘要每个来源属于一个检索任务
research_evidence原文片段、解释及问题关联每条证据指向一个来源

research_plans.run_id 和 research_events.run_id 都指向所属任务。计划以任务 ID 为主键；事件序号和任务 ID 共同构成主键，使每个任务的事件能按顺序补发。M2 的检索任务、来源和证据也用 run_id 归属到同一次运行。

6. SQLAlchemy 帮了什么忙

没有 ORM 时，代码需要手写大量 SQL，并手动把查询结果转换成 Python 对象。当前项目用 ResearchRunRow 和 ResearchEventRow 描述表结构，再通过异步 Session 执行查询与提交。SQLAlchemy 的异步接口由官方 Asyncio 文档定义。

ORM 不等于数据库，也不会替数据库保存数据。它只是应用代码与数据库之间的翻译和管理层。

7. 两种 commit 不要混淆

  • await session.commit()：提交数据库事务，让本次数据修改生效；
  • git commit：记录源代码和文档版本。

它们只有英文单词相同，处理的是完全不同的系统。

8. 用只读命令观察数据库

停止后端不是只读查询的硬性要求，但初学阶段先停止后端更容易排除并发干扰。在仓库根目录执行：

.\.venv\Scripts\python.exe -c 'import sqlite3; db=sqlite3.connect("file:var/researchflow.db?mode=ro", uri=True); print(db.execute("SELECT name FROM sqlite_master WHERE type=? ORDER BY name", ("table",)).fetchall()); db.close()'

它使用 Python 自带的 sqlite3 接口以只读模式打开文件并列出表，不需要安装 SQLite CLI。详细备份和重置步骤见 开发与运维手册。

9. 为什么 MVP 先用 SQLite

它占用资源少、没有独立服务、备份就是复制文件，非常适合 Windows 本地演示。代价是高并发、多实例部署和复杂运维能力有限。未来正式部署时可以迁移到 PostgreSQL；Repository 边界会降低业务层受到的影响，但数据库模型、迁移和部署配置仍需修改。

10. 检查理解

  1. 为什么不需要为当前项目启动 SQLite 服务？
  2. aiosqlite 和 SQLAlchemy 各解决什么问题？
  3. 为什么关闭后端再启动，研究历史仍然存在？
完成后查看参考答案
  1. SQLite 嵌入后端进程，后端直接读写数据库文件，没有独立服务器。
  2. aiosqlite 提供异步桥接；SQLAlchemy 管理映射、查询、Session 和事务。
  3. 任务已经提交到磁盘中的数据库文件，进程退出不会删除该文件。
实践任务：创建一个研究任务，记住标题；停止前后端并重新启动；确认历史记录仍在。然后用自己的话解释“进程内存消失了，为什么数据没有消失”。把解释发给我后，我们再判断是否真正掌握了持久化。
