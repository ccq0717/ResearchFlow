# M3 Exa 来源覆盖度评测

> 验证日期：2026-08-26  
> 结论：当前不需要额外接入学术检索 Provider

## 方法

运行 `scripts/evaluate_exa_coverage.py`，分别使用偏向学术论文、官方文档/标准和工业研究的三条固定自然语言查询。每条查询取前 5 个结果；只要至少 1 个结果被归一化为预期类型，该类即通过。查询不使用网站白名单或 Exa `category`，因此仍验证通用 Web 搜索能力。

```powershell
.\.venv\Scripts\python.exe scripts\evaluate_exa_coverage.py
```

该命令读取本地 `.env` 的 Exa Key，执行 3 次真实搜索，只输出标题、URL、类型、作者和发布时间等公开元数据，不输出密钥或正文。它是需要明确执行的外部服务评测，不属于离线自动化测试。

## 结果

| 查询方向 | 预期类型命中 | 代表性来源 | 结果 |
| --- | ---: | --- | --- |
| 同行评议论文与公开基准 | 5 / 5 | ICLR Proceedings、NeurIPS Proceedings、ACL Anthology、arXiv | 通过 |
| 官方文档与公开标准 | 2 / 5 | 新加坡政府开发者文档、ETSI 标准 | 通过 |
| 工程博客与工业研究 | 3 / 5 | Faros AI、Opsera、DX | 通过 |

Exa 同时在工业查询中返回了 arXiv 和 Science 论文，说明通用查询可以混合发现多种来源，而不需要为论文预先切换独立 Provider。

## 发现与决策

- Exa 的论文覆盖足以跑通当前黄金场景，额外学术 Provider 暂无必要；
- 作者和发布时间并非每个结果都有，ResearchFlow 会保存可用值并对缺失值保持为空；
- 发布机构由来源域名确定性归一化，不把作者误当作机构；
- 来源分类是可解释的保守规则，未知网站归为 `other`，不由 LLM 猜测；
- 后续如果需要 DOI、期刊、卷期、被引量或同行评议状态等专业元数据，再评估独立元数据增强服务，而不是替换当前通用搜索接口。
