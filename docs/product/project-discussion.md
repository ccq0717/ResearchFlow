# ResearchFlow 产品定位与设计取舍

> 状态：当前共识
>
> 更新日期：2026-08-27

本文只记录稳定的产品定位和关键取舍。实施顺序见[路线图](roadmap.md)，当前实现见架构文档；[MVP 技术规格](mvp-spec.md)仅保留最初纵向闭环的验收基线，阶段性过程见 `retrospectives/`。

## 1. 产品定位

ResearchFlow 是面向科研与技术预研场景的 AI 深度研究工作台。用户提供开放式研究目标和可选本地资料，系统拆解问题、检索公开网页、提取证据和主张，并生成带可追溯引用的结构化报告。

典型用途：

- 科研 Idea 与技术方向调研；
- 学术界和工业界进展比较；
- 论文、公开网页和个人资料的联合研究；
- 技术选型、竞品分析、文献综述与评测方案。

项目同时是一项 AI 全栈工程作品，应能够运行、演示、测试、部署和清楚讲解，而不是通用 Agent 平台或高并发 SaaS。

## 2. 黄金演示场景

首个完整场景是“设计 AI 代码生成工具评测方案”。系统应覆盖：

1. 结构化研究问题与检索词；
2. 学术、官方和工业公开资料；
3. 用户选择的本地 PDF、Markdown 或文本；
4. 可定位 Evidence 与显式 Claim—Evidence 关系；
5. 可执行的正确性、安全性和开发效率评测建议；
6. 带网页链接或本地页码/行号的 Markdown 报告。

## 3. 产品工作流

```text
研究目标
  → 结构化计划
  → 网页与本地资料检索
  → 正文读取和去重
  → Evidence 与 Claim 提取
  → 报告写作
  → 引用覆盖检查
  → 持久化和展示
```

工作流采用可控阶段和有限重试，不让多个 Agent 无限制自由对话。每一步都应有明确输入、输出、状态和安全失败方式。

## 4. 当前界面

- Dashboard：创建任务、管理知识文档、选择本地资料、查看历史；
- Research Workspace：展示计划、实时事件、来源、证据、主张和最终报告。

配置目前由服务端环境变量管理，不建设只会把密钥发送到浏览器的设置页面。独立知识库页面只有在 Dashboard 无法继续承载管理体验时再拆分。

## 5. 已确认技术取舍

- 前端：Next.js、React、TypeScript、Tailwind CSS；
- 后端：FastAPI、Pydantic、SQLAlchemy；
- 工作流：LangGraph 隐藏在 ResearchFlow 自有 `ResearchWorkflow` 接口后；
- LLM：OpenAI-compatible 适配器；
- 网页来源：Exa 通用搜索，不预设单独学术 Provider；
- 本地检索：Gemini Embedding + SQLite 向量存储，并保留 OpenAI-compatible 备选适配器；
- 通信：REST + SSE；
- 本地存储：SQLite 与文件目录；
- 本地开发：Windows 原生运行，不要求 Docker、Redis、GPU 或独立向量数据库。

## 6. 当前非目标

- 多租户计费与完整账号系统；
- 大规模分布式爬虫和高并发生产能力；
- 本地模型训练或微调；
- 多 Agent 群聊；
- 同时支持大量模型、搜索和文档 Provider；
- 在没有实际扩展需求时引入微服务、Redis 或 Kubernetes。

## 7. 作品集完成标准

- 新设备可按文档启动；
- 网页与本地知识联合研究可稳定演示；
- 来源、证据、主张和报告可追溯；
- 关键工作流有自动化测试和真实服务评测；
- 失败、超时、重启和敏感信息有明确处理；
- 可选在线 Demo 有访问保护、费用限制、持久化、备份和回滚说明；
- README、架构图、演示输入和实际能力一致。

作品集默认在本地运行并通过共享屏幕演示。若未来需要长期在线链接，部署指南保留 Railway Hobby、Singapore、共享访问码和每月 5–15 美元平台预算的可选方案，另计外部 Provider。
