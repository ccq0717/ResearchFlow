# ResearchFlow MVP 技术规格

> 状态：第一阶段实现基线
> 更新日期：2026-08-23

## 1. 目标

第一阶段交付一个可在 Windows 本地运行的模拟纵向闭环，用最少功能验证前端、后端、持久化和实时事件链路。

用户能够：

1. 在 Dashboard 输入研究目标；
2. 创建一个 Research Run；
3. 进入 Research Workspace；
4. 实时看到模拟的规划、检索、分析和写作进度；
5. 在任务完成后查看模拟报告；
6. 刷新页面或返回 Dashboard 后重新打开该任务。

本阶段不调用真实 LLM、搜索引擎或知识库。模拟工作流必须使用与未来真实工作流相同的应用接口和事件格式，后续只替换内部实现。

## 2. 用户故事

### US-01 创建研究任务

作为用户，我可以输入不少于 10 个字符的研究目标并创建任务，以便系统开始研究。

验收标准：

- 空目标或过短目标不能提交；
- 创建成功后返回唯一 `run_id`；
- 前端跳转到对应 Research Workspace；
- 任务初始状态为 `queued`。

### US-02 查看实时进度

作为用户，我可以看到研究阶段和研究事件持续更新，以便理解系统正在做什么。

验收标准：

- 前端通过 SSE 接收事件；
- 至少依次展示规划、检索、分析、写作和完成阶段；
- 事件断开时界面给出明确状态；
- 重复事件不会在界面重复追加。

### US-03 查看研究结果

作为用户，我可以在任务完成后查看结构化 Markdown 报告。

验收标准：

- 报告保存在数据库中；
- Workspace 展示任务状态和报告；
- 直接打开该任务 URL 时仍可读取结果。

### US-04 查看研究历史

作为用户，我可以在 Dashboard 查看并重新打开历史任务。

验收标准：

- 按创建时间倒序展示；
- 显示标题、状态和更新时间；
- 页面刷新后记录仍然存在。

## 3. 页面范围

### Dashboard

- 项目名称和简短介绍；
- 新研究输入框；
- 创建按钮和提交状态；
- 历史任务列表；
- 空状态和错误状态。

### Research Workspace

- 研究目标；
- 当前状态与总体进度；
- 研究阶段列表；
- 研究事件列表；
- 最终 Markdown 报告；
- SSE 连接状态。

知识库页面不属于第一阶段模拟闭环，在接入 RAG 时实现。

## 4. 后端接口范围

```text
GET  /health
POST /api/research-runs
GET  /api/research-runs
GET  /api/research-runs/{run_id}
GET  /api/research-runs/{run_id}/events
```

- 普通数据接口返回 JSON；
- `events` 使用 `text/event-stream`；
- 错误返回稳定的 `code`、`message` 和可选 `details`；
- 时间统一使用带时区的 ISO 8601 UTC 字符串。

## 5. 非功能要求

- Windows 10/11 可运行；
- 本地开发不要求 Docker、Redis 或 GPU；
- 后端使用 SQLite；
- 前后端均提供格式检查和基础测试；
- API Key 不进入 Git；
- 本地运行数据写入 `var/`；
- 页面具备桌面端和基本移动端适配；
- 模拟任务应在较短时间内完成，便于重复演示和测试。

## 6. 完成定义

满足以下条件才算第一阶段完成：

- 新环境能按照 README 启动；
- 前端和后端检查通过；
- 后端接口测试通过；
- 用户可完成“创建 → 实时查看 → 完成 → 刷新重开”闭环；
- 进程重启后历史任务仍存在；
- 仓库中不存在密钥、虚拟环境、依赖目录或运行数据；
- 关键设计与运行方式已记录在 `docs/` 和 README。
