# M1 阶段复盘：真实 LLM 最小接入

> 日期：2026-08-24
> 状态：已完成并在进入 M2 前复查

## 1. 本阶段范围

M1 在保留低资源模拟模式的前提下，引入 OpenAI-compatible LLM 适配器，让用户研究目标可以生成结构化研究计划，并把模型、耗时和 Token 用量展示到前端。

## 2. 做得有效的设计

- `ResearchWorkflow` 与 `LLMClient` 将应用层同模型供应商、HTTP 细节和未来 LangGraph 隔离；
- Fake LLM 和 Mock HTTP 固定了结构化输出、错误映射与持久化契约；
- 默认模拟模式不需要外部服务、Docker、GPU 或 API Key，符合 Windows 低资源演示目标；
- 一次非敏感的 OpenAI-compatible 真实冒烟测试成功，确认当前兼容适配器和配置可用。

## 3. 本次复查发现的问题与修复

### 3.1 终态与 SSE 终结事件存在竞态

旧实现先更新运行状态，再单独写入 `run.completed` 或 `run.failed`。SSE 可能在两步之间观察到终态并关闭，导致客户端收不到终结事件。现在由 `ResearchRunOutcome` 表达不可变结果，Repository 在一个 SQLite 事务中同时保存运行终态和全部终结事件。

### 3.2 失败信息已保存但前端没有明确展示

研究工作区现在提供独立错误面板，以可访问的 `role=alert` 展示安全错误消息和稳定错误码，不显示原始供应商响应。

### 3.3 后台任务关闭与异常恢复不完整

应用跟踪运行中的后台任务，关闭时取消并等待其释放数据库连接；下次启动会把遗留的 `queued` 或 `running` 记录标记为 `RUN_INTERRUPTED`，避免永久卡住。

### 3.4 自动化测试会继承开发者 `.env`

这是本阶段风险最高的问题。开发者切换到 `llm` 后，原有测试可能误用真实密钥并访问网络。所有 Settings 测试实例现已显式设置 `_env_file=None`，常规测试只使用 Fake 或 Mock。真实 API 冒烟测试与自动化测试严格分离。

### 3.5 环境文件副本可能被误提交

忽略规则由 `.env.*` 扩展为 `.env*`，并继续只放行 `.env.example`，因此类似 `.env copy.example` 的本地副本也不会进入 Git。

### 3.6 Windows 关闭路径偶发 SQLite 写锁

重复关闭测试发现，取消可能恰好发生在 aiosqlite 工作线程提交事务时，协程已退出但底层连接仍短暂持有写锁，导致随后保存 `RUN_INTERRUPTED` 失败。Repository 的会话边界现在会屏蔽二次取消，等待 rollback 和 close 完成后再继续传播取消。

## 4. 验证结果

- OpenAI-compatible 真实 API 冒烟测试成功生成 5 个研究问题，并记录了耗时与 Token 用量；
- 后端生命周期回归测试覆盖成功终结事件、关闭中断和启动恢复；SQLite 关闭测试在修复后连续运行 20 次通过；
- 后端测试、Ruff、前端 ESLint 与 Next.js 生产构建均纳入提交前检查；
- 冒烟记录不保存 API Key、完整提示词或模型输出。

## 5. 合理延期项

- 模拟工作流和 LLM 工作流仍有阶段生命周期重复。M2 引入 LangGraph 时会重塑真实编排，现在抽象公共基类容易制造错误边界，因此延期到 M2 一并处理；
- provider、model、耗时和 Token 是一组模型调用元数据，但目前只有一个主要消费者。等 M2 出现更多调用节点后再决定是否提取值对象；
- 完整浏览器 E2E、取消和重试属于 M5 范围；当前先以 API 生命周期测试和前端生产构建保护关键改动。

## 6. 进入 M2 的约束

- 每个里程碑结束后必须暂停复查实现、测试、接口、安全、资源占用和文档；
- 高风险问题在进入下一阶段前修复，延期项必须记录原因和目标里程碑；
- 常规测试不得读取 `.env` 或访问真实供应商；
- LangGraph 类型不得泄漏到 FastAPI、领域模型和前端事件契约。
