# M4 阶段复盘：本地知识库与联合检索

> 日期：2026-08-26  
> 结论：M4 完成，可以进入 M5

## 已交付

- Dashboard 支持上传、查看、选择、重新处理和删除 PDF、Markdown、UTF-8 纯文本；
- 后端限制类型、大小、数量、PDF 页数和解析文本总量，文件使用 UUID 存储名，失败状态可查询；
- 文档与片段持久化到 SQLite，片段保留页码或行号；
- `langgraph` 模式把所选本地文档和 Exa 网页共同检索为运行内 Source，复用 Evidence、Claim 和引用覆盖检查；
- 研究材料界面区分网页与本地来源，本地引用可以打开原文件并显示定位；
- 文档片段向量持久化到 SQLite，并通过 `KnowledgeRetriever` 完成本地检索。

## 三轴阶段门禁

### 1. 实现质量

知识文档生命周期集中在 `KnowledgeLibrary`，解析、检索和持久化各自保持独立职责；研究工作流只依赖 `KnowledgeRetriever` 接口。自动化测试覆盖安全文件名、重复文件、类型和体积限制、PDF 文本与空白 PDF、持久化重开、重处理、删除清理、文档选择以及本地来源进入完整引用链路。

门禁审查发现并修复了关联清理方向错误：重新处理原本会误删运行—文档选择关系，而删除文档没有显式清理该关系。现在重处理保留选择关系，失败时清空旧片段；删除才统一清理片段和运行关联，并由回归测试固定语义。

已知边界是 PDF 不执行 OCR，上传解析仍在 API 请求生命周期内，检索是面向小规模作品集的进程内计算。三者均有明确错误或资源上限，不伪装成大规模生产能力；后台处理、OCR 和大型索引只有在实际需求出现时再引入。

### 2. 实现—文档一致性

领域词汇表、数据模型、工作流架构、仓库结构、SSE、开发运维、部署指南、学习课程、README 与路线图均已同步。配置模板只保留常用外部服务设置，高级限制与默认值由 `Settings` 和运维手册集中说明；数据库备份说明同时覆盖 SQLite 和原始上传文件。

### 3. 设计演进

本地命中先转换为 Source 的设计得到验证，Evidence 和引用审计无需分叉。M4 首版固定评测曾支持使用词法方案；随后根据语义召回和作品集展示需求，检索实现升级为 Gemini Embedding，但继续沿用单实例 SQLite，不增加独立向量数据库。后续 M5 重点仍是任务可靠性、E2E、部署安全、费用控制和作品集交付。

### Embedding 跟进调整

2026-08-26 的跟进改动移除了词法/字符 n-gram 模式，新增 `EmbeddingClient` seam、Gemini 原生适配器、OpenAI-compatible 备选适配器和 Fake 测试适配器。适配器按模型版本翻译文档/查询用途：Gemini Embedding 2 使用文本任务指令，Gemini Embedding 1 使用任务类型字段；模型、维度或指令策略改变后必须重新处理文档，避免混算不兼容向量。自动化测试和真实 Gemini Embedding 验证均已通过。

## 真实服务验证

早期使用仓库公开的 `security.txt` 与本机配置的真实 LLM、Exa 在 `langgraph` 模式完成过一次联合研究：共保存 23 个来源，其中 1 个为带“第 1–4 行”定位的本地来源；形成 19 条 Evidence 和 19 条 Claim，确定性引用覆盖率为 100%，最终报告包含本地文件名与定位。

Embedding 升级后，使用 `gemini-embedding-2`、768 维向量运行三条固定中文查询，Top-1 Accuracy 与 MRR@3 均为 1.000；现有 `security.txt` 也已通过真实 Gemini 重新处理。修正本机 LLM Base URL 后，完整 `langgraph` 回归成功完成：保存 25 个来源，其中 1 个为带“第 1–4 行”定位的本地来源；形成 11 条 Evidence 和 11 条 Claim，确定性引用覆盖率为 100%，并生成 7,425 字符报告。自动化测试仍只使用 Fake/Mock，不消耗外部额度。

## 进入 M5 前保留事项

- 任务仍在 API 进程内执行，重启只能标记中断，不能续跑；
- 在线 Demo 必须限制上传访问、文件数量与费用，并将数据库和上传目录一起放在持久磁盘并备份；
- 正式公开部署前需要数据库迁移方案、访问保护、限流和日志隐私检查。
