# M1 可用性跟进复盘

> 日期：2026-08-24
> 触发：首次真实前端体验反馈

## 1. 本次范围

修复日志时间显示、重新进入任务后日志丢失和毫秒耗时不易阅读的问题，并补充研究历史完成时间。

## 2. 发现与修复

- SQLite 会丢失 Python `datetime` 的时区标记。Repository 现在把读出的无时区时间恢复为 UTC，API 保证输出 `Z` 或 `+00:00`；
- 事件一直保存在 `research_events`，但前端重进页面只读取任务和计划。新增事件历史 API，前端先加载历史，再从最后序号继续 SSE；
- 模型调用仍以毫秒精确保存，前端改为自适应“秒/分/时”格式，并用悬停标题保留毫秒值；
- Dashboard 现在显示研究记录的完成或更新时间；
- Dashboard 中过时的“纯模拟 MVP”说明已改为符合当前 M1 状态的描述。

## 3. 验证

- 新增回归测试先稳定复现历史接口缺失，修复后通过；
- 后端测试验证旧 SQLite 数据也能输出 UTC 标记；
- 隔离模拟环境完成“创建 → 完成 → 重进”验收：两次读取均恢复 14 条事件，首尾为 `run.queued` 和 `run.completed`，原始 JSON 时间带 `Z`；
- 从历史最后序号继续 SSE 时只收到 `stream.ready`，没有重复推送旧事件；
- Dashboard 与任务页面均返回 HTTP 200，前端 ESLint、TypeScript 和 Next.js 生产构建通过；
- 当前会话缺少应用内浏览器控制工具，因此无法自动点击和截图；已用完整 API 流程和页面可访问性检查替代，视觉效果仍由用户刷新页面确认。

## 4. 延期与下一步

- 研究记录重命名、删除和归档值得实现，但需要明确进行中任务约束、删除确认和数据级联策略，已作为独立路线项记录；
- 完整浏览器 E2E 仍归 M5，后续应覆盖“创建 → 返回 → 重进 → 日志仍在”的真实导航；
- M2 多节点工作流将产生更多调用指标，届时再实现端到端耗时、阶段耗时和累计 Token，而不是把单次规划耗时误称为总耗时。
