# ResearchFlow 作品集展示材料

## 一句话介绍

ResearchFlow 是面向科研与技术预研的证据优先研究工作台：它把开放目标拆成计划，联合检索公开网页和本地资料，并生成每条关键主张都能追溯到证据与来源的报告。

## 两分钟演示

1. 在 Dashboard 选择一份本地资料并提交黄金研究目标；
2. 在工作区展示 LangGraph 阶段、SSE 进度和结构化计划；
3. 展示学术、官方、工业和本地来源，以及 Claim—Evidence—Source 关联；
4. 打开 Markdown 报告中的网页引用或本地文件定位；
5. 展示耗时、Token、来源构成和引用覆盖率；
6. 刷新页面证明状态可恢复，再简短展示取消、一次重试和历史管理。

固定输入与公开结果样例位于 `examples/`，演示前不需要临时设计问题。

## 简历描述

设计并实现 AI 深度研究工作台 ResearchFlow，使用 Next.js、FastAPI、LangGraph 与 SQLite 打通结构化规划、Exa 通用 Web 检索、Gemini Embedding 本地 RAG、证据提取和可追溯 Markdown 报告；通过自有 Provider 接口隔离外部服务，并补齐 SSE 状态恢复、取消/有限重试、运行度量、离线集成测试、浏览器 E2E、备份与容器化交付。

## 完整项目描述

**面向科研与技术预研的可追溯 AI 深度研究工作台**

Python，TypeScript，Next.js，LangGraph，SQLite

1. **项目内容：** 针对通用大模型研究过程不透明、结论与原始资料难以对应，以及公开网页和个人文档相互割裂的问题，构建 ResearchFlow 深度研究工作台，将开放式研究目标转化为结构化计划、可检查证据和带引用报告。
2. **项目设计：** 设计“规划—联合检索—证据化写作”三阶段流程：
   1. **研究规划：** LLM 通过结构化输出生成研究问题、检索词与预期交付物；
   2. **联合检索：** 使用 Exa 搜索公开网页，并通过 Embedding 与余弦相似度检索用户选择的 PDF、Markdown 和纯文本片段，统一转换为可定位的 Source；
   3. **证据化写作：** 将原文整理为 Evidence，把报告关键 Claim 显式关联到证据，并通过确定性引用审计检查关联完整性。
3. **项目实现：** 使用 LangGraph 编排规划、搜索、阅读、分析、写作和检查节点，以自有接口隔离 LLM、搜索、网页读取与 Embedding 供应商；Next.js 与 FastAPI 通过 REST 和 SSE 连接，SQLite 持久化运行状态、事件和研究材料，并支持取消、有限重试、刷新恢复、历史管理与运行度量。
4. **项目成果：** 完成支持真实 LLM、Exa、Gemini Embedding 和本地 PDF 的全链路作品集 Demo，同时提供无外部调用的模拟模式；通过 Fake、HTTP Mock、检索评测、前后端自动化测试、浏览器 E2E 和 GitHub Actions 分层验证代码与外部协议，提供可选的 Docker 和在线部署方案。

引用覆盖率只表示全部关键主张都关联了已保存证据，不证明事实准确性、来源权威性或建议有效性。当前没有人工盲评或专家评分，因此不报告虚构的“报告质量分数”。

## 面试重点

- 为什么采用可控阶段工作流，而不是多个 Agent 自由对话；
- 为什么当前用 Exa 通用搜索而不额外接入学术 Provider；
- 为什么用 Embedding + SQLite，而不是词法匹配或独立向量数据库；
- Claim、Evidence、Source 为什么分开建模，以及引用覆盖率不能证明什么；
- 为什么失败重试创建新运行，而不伪装成尚未实现的 checkpoint 恢复；
- SQLite、进程内任务和单实例部署的适用边界，以及何时才需要队列和 PostgreSQL。

## 展示方式与边界

默认在面试中本地运行并共享屏幕，提前用黄金输入确认外部服务可用；GitHub 页面长期展示架构、示例结果和技术取舍。在线 Demo 是可选增强，不是作品集成立的前提。若公开部署，只使用公开资料、访问码、固定任务上限和费用预算；未真实验证的在线能力、成本或高可用性不写入简历。
