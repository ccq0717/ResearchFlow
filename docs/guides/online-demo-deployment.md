# ResearchFlow 作品集在线 Demo 部署指南

> 状态：规划中；M4 本地核心研究闭环已完成，待 M5 实施并逐步验证
> 目标：提供一个可由面试官通过链接访问的低流量作品集 Demo
> 最后更新：2026-08-25

## 1. 文档范围

本文记录 ResearchFlow 从本地 Demo 演进为作品集在线 Demo 时需要完成的准备、部署、验证和维护工作。它面向少量受邀访问者，不把项目描述为已经具备多用户生产系统的可靠性。

本地初始化、日常开发、测试和排错仍以[使用、开发与运维手册](development-and-operations.md)为准。本文中的部署步骤只有在实际平台上验证后才能标记为可用；尚未验证的内容只表示目标或选择标准。

## 2. 部署目标与非目标

### 2.1 目标

- 面试官可以通过一个稳定的 HTTPS 链接打开 ResearchFlow；
- 用户可以运行预设或受限的研究任务，看到实时进度、来源、证据和报告；
- 部署成本、模型费用和外部搜索费用有明确上限；
- API Key 等密钥只保存在部署平台的 Secret 中；
- 应用和数据在普通进程重启后仍可恢复到文档声明的程度；
- 项目可以通过可复现的构建、部署和回滚步骤维护。

### 2.2 非目标

- 不开放公众注册，不建设完整账号体系或多租户平台；
- 不承诺高并发、高可用或零停机升级；
- 不为了在线 Demo 提前引入 Kubernetes、微服务或复杂云基础设施；
- 在单实例能够满足演示前，不强制引入 PostgreSQL、Redis 或分布式任务队列；
- 不保存访问者上传的私人资料或其他不适合公开演示的数据。

## 3. 当前上线阻塞项

当前仓库可以在本地运行，但还不能直接暴露到互联网。上线前至少需要解决：

- **访问控制：**当前 API 没有鉴权，访问者可以创建任务并查看全部研究历史；
- **费用控制：**需要限制任务频率、并发数、单次研究预算和每日总预算；
- **持久化：**SQLite 数据库和原始上传目录必须位于同一持久磁盘或持久卷，不能放在随部署消失的临时文件系统；
- **进程生命周期：**研究任务当前运行在 FastAPI 进程内，服务重启会中断任务，现有恢复语义是标记失败而不是继续执行；
- **单实例约束：**在任务状态仍保存在进程内且数据库仍为 SQLite 时，API 只能运行一个实例和经过验证的单进程配置；
- **安全入口：**需要 HTTPS、反向代理或平台入口、合理的请求体限制和速率限制；
- **运维能力：**需要日志、健康检查、备份、恢复、更新和回滚方法；
- **演示内容：**必须使用公开、安全、费用可控的固定演示输入，不能暴露密钥、个人路径或私人研究数据。

这些约束应在 M5 实现过程中持续复查。若工作流、存储或部署模型发生变化，应同步更新本文。

## 4. 目标部署架构

第一版在线 Demo 优先采用简单的单机或单区域单实例架构：

```text
浏览器
   │ HTTPS
   ▼
云平台入口或反向代理
   ├── /        → Next.js Web（单实例）
   └── /api/*   → FastAPI API（单实例）
                         │
                         ├── 远程 LLM / 搜索 Provider
                         └── 持久磁盘中的 SQLite、上传文件与演示数据
```

优先让前后端使用同一站点入口，以减少 CORS、SSE 和访问控制的额外复杂度。若部署平台要求分离域名，必须显式配置前端 API 地址、后端 CORS、HTTPS 和 SSE 连通性。

SQLite 只作为低流量单实例在线 Demo 的阶段性选择。出现多实例、并行写入压力、正式账号数据或更强恢复要求时，应重新评估 PostgreSQL、数据库迁移和独立后台 Worker，而不是直接横向扩展当前 API。

## 5. 平台选择标准

部署平台和预算尚未确认。评估候选平台时至少比较：

- 是否支持长期运行的 Web 服务和 SSE，而不是只支持短时 Serverless 请求；
- 是否提供持久磁盘，部署和重启后是否保留 SQLite 数据；
- 是否支持从 Git 仓库或容器镜像部署；
- 是否提供 HTTPS、自定义域名和 Secret 管理；
- 是否支持健康检查、自动重启、日志查看和快速回滚；
- 空闲休眠、冷启动和最长请求时限是否会破坏研究任务或 SSE；
- CPU、内存、磁盘、出站流量以及 LLM/搜索调用的月度总成本；
- 是否方便设置访问保护、限流和费用告警；
- 服务和数据所在区域是否满足演示数据与外部 Provider 的要求。

最终选择平台时，应在本文记录选择日期、费用、限制、放弃其他候选项的原因和实际验证结果。

## 6. 上线前安全与费用检查

### 6.1 最小访问保护

在线 Demo 至少采用一种经过验证的访问保护方式，例如部署平台访问策略、反向代理口令或应用内演示访问码。选择前需确认它不会破坏浏览器对 REST API 和 SSE 的访问。

无论采用哪种方式，都不能让未授权访问者读取历史研究记录。公开链接若必须免登录，应只展示预置结果，并把创建真实研究任务的能力单独保护或限制。

### 6.2 费用边界

上线前需要确定并实现：

- 同一访问者的请求频率限制；
- 全站同时运行的研究任务上限；
- 单个任务的搜索次数、网页数量、模型 Token 和重试上限；
- 每日或每月费用上限及达到上限后的安全失败方式；
- Provider 侧预算、余额或告警设置；
- 不把供应商原始错误、密钥或敏感上下文返回给前端。

### 6.3 Secret 与公开数据

- LLM、搜索和其他 Provider 密钥只进入平台 Secret；
- 不把生产 `.env`、数据库、备份或访问日志提交到 Git；
- 前端 `NEXT_PUBLIC_*` 变量会暴露给浏览器，不能存放任何密钥；
- 在线 Demo 只使用可公开的研究目标、来源和固定样例；
- 若开放上传，必须校验类型和大小、限制数量、使用不可猜测存储名，并明确告知资料会交给外部 LLM；作品集首版更适合只提供预置公开文档或把上传能力置于访问保护之后；
- 日志不得记录完整密钥、私人资料、受版权保护的全文或不必要的模型上下文。

## 7. 数据持久化与备份

第一版计划继续使用 SQLite，但必须满足：

- `RESEARCHFLOW_DATABASE_URL` 指向持久磁盘中的明确路径；
- `RESEARCHFLOW_KNOWLEDGE_UPLOAD_DIRECTORY` 指向同一持久磁盘中的明确目录；
- API 只运行一个会写入该数据库的实例；
- 部署更新不会覆盖或删除数据库文件；
- 将数据库与上传目录作为一致的数据集建立自动备份，并限制备份保留数量；
- 至少进行一次从备份恢复到临时环境的演练；
- 发布前说明哪些状态可以恢复，哪些运行中的任务会在重启后失败；
- 删除或重置在线演示数据前先确认目标路径并保留可恢复备份。

平台确认后，在此补充经过验证的磁盘挂载、备份、恢复和数据重置步骤。

## 8. 部署实施顺序

以下是计划顺序，不代表当前已经完成：

1. 使用已完成的 M4 网页与本地资料联合研究闭环、黄金演示输入和公开知识样例作为上线验收基线；
2. 确认在线 Demo 的功能边界、访问方式和费用预算；
3. 增加前端与后端的可复现容器构建；
4. 增加仅用于本地验证部署拓扑的 Compose 配置；
5. 实现最小访问保护、并发限制和研究预算；
6. 选择支持 HTTPS、SSE、Secret 和持久磁盘的平台；
7. 配置域名、环境变量、持久磁盘、日志和健康检查；
8. 部署到临时环境，验证构建、启动、SSE、任务终态和数据持久化；
9. 执行安全、费用、备份与恢复检查；
10. 使用黄金演示输入完成线上端到端验收；
11. 记录实际命令、平台界面操作、已知限制和回滚步骤；
12. 验收通过后才把链接加入 GitHub README、简历或作品集。

## 9. 上线验收清单

### 9.1 构建与启动

- [ ] 干净环境能够使用锁文件完成前后端构建；
- [ ] 容器或服务启动后健康检查通过；
- [ ] 服务异常退出后能够自动重启；
- [ ] 部署步骤中不需要手工复制未记录的文件。

### 9.2 用户流程

- [ ] HTTPS 首页可以打开且没有混合内容警告；
- [ ] 受邀访问者能够按预期通过访问保护；
- [ ] 可以创建受限研究任务并看到 SSE 实时进度；
- [ ] 研究计划、来源、证据和报告能够正确显示；
- [ ] 预置本地资料能够被选择、检索并显示可定位引用；若开放上传，类型、大小、数量和访问保护均生效；
- [ ] 刷新或重新打开页面后能够恢复已持久化内容；
- [ ] 失败、超时和达到预算上限时显示安全、明确的错误。

### 9.3 数据、安全与费用

- [ ] 部署和普通重启后 SQLite 数据与上传文件仍存在且对应一致；
- [ ] 已完成一次备份和恢复演练；
- [ ] 浏览器、页面源代码、日志和错误响应中没有密钥；
- [ ] 未授权访问者不能读取研究历史或触发付费任务；
- [ ] 并发、频率、Token、搜索次数和总费用均有上限；
- [ ] 数据库、备份和访问日志不会进入 Git。

### 9.4 运维与作品集交付

- [ ] 已记录部署平台、区域、资源规格和月度预算；
- [ ] 已记录更新、回滚、备份、恢复和停机步骤；
- [ ] 已记录当前单实例与任务中断限制；
- [ ] README 中的在线链接、截图和能力说明与实际部署一致；
- [ ] 演示前可以用一份短清单检查服务、费用和敏感信息。

## 10. 日常维护、更新与回滚

平台确定并完成首次部署后，本节应补充可直接执行且已验证的内容：

- 如何查看健康状态、日志、磁盘容量和费用；
- 如何备份数据库并验证备份可读；
- 如何部署新版本，以及部署前如何处理正在运行的任务；
- 如何判断新版本异常并回滚到上一个镜像或版本；
- 如何恢复数据库，如何确认恢复目标不会覆盖错误环境；
- 如何临时关闭任务创建、切换维护状态或停止付费 Provider；
- 如何轮换密钥并确认旧密钥已经失效。

在这些步骤实际验证前，不把本文称为完整运行手册。

## 11. 已确认与待确认选择

### 11.1 已确认

- 部署用途是作品集在线 Demo，不是开放注册的正式 SaaS；
- 面向面试官和少量受邀访问者，优先低成本和低维护复杂度；
- 第一版优先单实例，可阶段性继续使用持久磁盘上的 SQLite；
- 本地核心研究闭环稳定后再实施线上部署；
- 部署配置、线上验收和回滚记录属于 M5 作品集交付的一部分。

### 11.2 待确认

- 部署平台、区域和月度预算；
- 域名以及前后端使用同域还是分离域名；
- 最小访问保护方式；
- LLM 与搜索 Provider 的线上模型、额度和费用上限；
- SQLite 与上传目录的持久磁盘、备份位置和保留周期；
- 是否需要展示固定报告作为 Provider 不可用时的只读降级方案；
- 何时需要从进程内任务与 SQLite 升级到独立 Worker 和 PostgreSQL。

## 12. 文档维护规则

- 尚未执行的步骤使用“计划”“待确认”或未勾选状态，不写成已经可用；
- 只记录在目标平台上实际验证过的命令、路径和平台设置；
- 部署架构、环境变量、端口、域名、持久化、费用或安全边界变化时同步更新本文；
- 每次上线验收记录日期、版本、结果和已知限制；
- README 只保留在线链接、能力摘要和本地快速开始，部署细节统一以本文为准。
